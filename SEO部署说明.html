航天宏图 技术博客 项目 · 2026 年 8 月 10 日

为什么需要改？

每篇交付的 HTML 文章中，都预置了完整的 SEO 标签（搜索引擎优化元数据）。这些标签决定了：

  • 文章在 Google/百度搜索结果中的展示效果
  • 在微信/朋友圈/微博分享时显示的卡片标题和封面图
  • 搜索引擎把哪个 URL 认定为"原始版本"（避免被判定为重复内容降权）

目前这些标签中的 URL 指向的是我们用于预览的 GitHub 地址（haibin-yu.github.io）。这只是协作审核用的临时地址，不是官网正式地址。如果部署到 piesat.cn 后不替换这些 URL，会出现以下问题：

问题如果不改会发生什么严重程度
搜索引擎降权 canonical 标签告诉 Google："这篇文章的正版在 GitHub"。搜索引擎会把 piesat.cn 上的页面当成复制内容，不给排名。 严重
分享链接错误 用户从官网把文章分享到微信或朋友圈时，og:url 会使分享卡片跳转到 GitHub 地址，而不是官网。 严重
分享卡片无封面图 og:image 指向 GitHub 上的图片地址。如果未来 GitHub 仓库删除或重命名，分享出去的文章卡片会丢失封面图。 中等

每篇文章需要改什么？

每篇 HTML 中需要替换 3 个标签。以下以 A1 文章为例，原始值（左）→ 替换为官网实际值（右）：

标签当前值（GitHub 预览）替换为官网实际 URL
<link rel="canonical"> haibin-yu.github.io/piesat-prod/article-a1-piesat.html 官网 A1 文章的实际 URL
<meta property="og:url"> haibin-yu.github.io/piesat-prod/article-a1-piesat.html 官网 A1 文章的实际 URL（同上）
<meta property="og:image"> haibin-yu.github.io/piesat-prod/zhijiang-airport.jpg 封面图在官网 CDN 上的实际 URL

4 篇文章的 HTML 文件中，搜索 haibin-yu.github.io 即可定位所有需替换的位置。每篇只有 3 处（canonical + og:url + og:image），其余标签无需修改。

操作步骤

  1. 打开交付包中每篇文章的 HTML 文件（如 article-a1-piesat.html）
  2. 全局搜索替换 haibin-yu.github.io/piesat-prod/ → 替换为官网图片目录的路径（如 www.piesat.cn/images/blog/）
  3. 手动修正 3 个 SEO 标签的完整 URL（canonical、og:url、og:image），确保指向官网的完整 https 地址
  4. 部署到官网服务器

内链处理方案

每篇文章末尾有"相关推荐"链接指向其他文章，正文中也有相互引用的内链。如果这些链接指向的 URL 不正确，会形成大量死链，影响用户体验和 SEO。

已上线文章：已知真实 URL

我们从官网博客列表页确认了已发布文章的实际 URL 结构：

编号标题官网实际 URL状态
A1 雷达卫星为什么能穿透云层？SAR成像原理三分钟看懂 /website/cn/pages/blog/bloginfo/2581.html 已上线
A2 SAR卫星能做什么？六大领域应用全景 /website/cn/pages/blog/bloginfo/2631.html 已上线

URL 结构为：/website/cn/pages/blog/bloginfo/{数字ID}.html。这些已知 URL 可以直接写入 HTML 内链，部署后即生效。

未发布文章：提前写入真实 URL

对于尚未发布的新文章（A3、B1 等），内链有两种处理方式：

方案做法问题
❌ JS 占位提示 内链用占位符，点击时用 JS 检测目标页面是否存在，不存在则弹窗"文章暂未发布" 引入不必要的 JS 复杂度；每次点击有网络延迟；文章发布后需人工回改所有旧文章的链接，容易遗漏
✅ 提前写入真实 URL 客户发布新文章前告知数字 ID，我们提前将所有内链替换为正确的官网 URL，一次性交付 需要客户提供 ID（我们会在交付前主动询问）
✅ 推荐方案：提前写入真实 URL，我们负责所有内链替换

您只需要在发布新文章时告诉我们数字 ID（如 2631），我们会：

  1. 更新新文章自身的 SEO 标签（canonical / og:url / og:image）
  2. 更新所有已发布文章中指向该新文章的内链
  3. 更新新文章正文中指向已发布文章的内链
  4. 重新打包交付，所有内链全链路接通

这样您拿到的是一个"全链路已接通"的最终版本，部署后无需再修改任何链接。我们负责改，您负责部署，边界清晰。
