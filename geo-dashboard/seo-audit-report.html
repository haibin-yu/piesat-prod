三、5 个问题（按优先级）

P0 · 致命

sitemap.xml 未收录博客文章

现象

https://www.piesat.cn/sitemap.xml 共 1058 个 URL，没有一条是 blog / bloginfo 条目。

影响

搜索引擎无法通过 sitemap 发现博客文章，只能靠爬虫偶然爬到；而官网博客路径深、权重低，爬虫很难摸到，导致文章长期不被收录。

修复

把 7 篇博客 URL 加进 sitemap.xml（或单独生成博客 sitemap，再在 sitemap.xml 里引用）——长效自动化（让新文章自动进 sitemap + 自动推送百度）见第八章。

实测佐证（2026-08-31）

sitemap.xml 共 1058 个 URL，百度已收录 1052 个（收录率 99%）；而博客目录 bloginfo 仅 2 条被收录（A4 女娲星座组网 / B2 海洋监测），其余 5 篇全部未收录——正是「进 sitemap 的几乎全收、不进 sitemap 的几乎全漏」的直接后果。

P0 · 致命

robots.txt 屏蔽了所有文章图片

现象

robots.txt 含以下规则，而文章图片全部位于 /uploads/ 目录：

Disallow: /uploads/
Disallow: *.jpg$
Disallow: *.png$
Disallow: *.gif$
影响

文章配图完全无法被搜索引擎抓取，图片 SEO 全废；AI 引擎也抓不到图片信息。

修复

放开 /uploads/ 下的图片抓取（去掉 Disallow: /uploads/ 及图片扩展名规则），或将博客图片迁移到未被屏蔽的目录。

P1 · 重要

canonical 缺失 + 结构化数据 URL 错误

现象
  1. 单篇文章页没有 <link rel="canonical">；
  2. JSON-LD 中 mainEntityOfPage.@id 写的是 https://www.piesat.cn/blog/sar-radar-principle（不存在的路径），而文章真实 URL 是 https://www.piesat.cn/website/cn/pages/blog/bloginfo/2581.html。
影响

搜索引擎收到一个错误 / 缺失的规范地址信号，无法正确识别页面的权威 URL。

修复

单篇加 canonical 指向真实 URL；JSON-LD 的 mainEntityOfPage.@id 与 image（当前为相对路径 /uploads/...）改为绝对 URL。

P1 · 重要

datePublished 日期错误

现象

JSON-LD 的 datePublished / dateModified 为 2026-07-15，与文章实际发布（2026-08）不符。

影响

时效性信号错乱。

修复

改为真实发布日期。

六、背景说明（为什么官网排不过百家号 / 头条号）

  1. 平台权重：百家号（baijiahao.baidu.com）是百度自家平台，天然享受最高权重倾斜；头条号同理。独立域名要超它，本质上是在对抗平台自己的生态。
  2. 技术配置缺口：本报告列出的 5 个问题，让官网博客「该被收录的没进 sitemap、该被抓的图片被 robots 挡住、该明确的规范地址是错的」。
  3. 时间积累：文章 8 月刚上线，域名权重、外链、被引用量需要时间沉淀。

修复上述 P0/P1 问题后，官网博客才有进入百度首页（前 10）的技术基础；目标应定为「官网进首页、与百家号并存」，而非「盖过百家号排第一」。

七、流量数据层发现（百度站长平台第一方数据 · 2026-08）

数据来源为百度站长平台导出的第一方搜索数据（PC 端 31 词 + 移动端 152 词）。与前五章「技术配置排查」不同，这是用户在百度真实搜索、官网被真实展现 / 点击的回流数据（非人工抽样），反映的是「收录之后的转化表现」。

7.1 品牌词：排名不差，但点击率极低

「航天宏图」PC 端排名第 7，点击率仅 4.44%（展现 45 次、点击 2 次）。排名本身不算差，问题在标题 / 描述不够吸引人，或搜索结果被百科、股票站占据，用户看到了却点别人。建议优化品牌相关页面的 title + description，强化「卫星遥感 / SAR / 女娲星座」差异化标签。

7.2 移动端：152 词点击几乎归零

移动端 152 词，总展现 326 次、总点击仅 9 次；品牌词「航天宏图」在移动端首页展现 89 次、点击 0。移动端是百度主要流量入口，但转化率是灾难级的——要么排名太靠后（移动端前 10 才有点击），要么落地页移动端体验差。建议重点排查移动端排名分布 + 移动端页面加载与排版体验。

7.3 商业意向词：有真实需求，但排名 40 开外

「智慧应急监测系统 推荐 / 供应商 / 厂家 / 哪家好 / 龙头」一组词，PC 端排名 34–43。这是公司核心业务（应急监测），用户在明确「找供应商」，但官网排名 40 开外，基本没有商业转化机会，是最该优先抢的词群。建议针对性产出「智慧应急监测」专题内容（方案页 / 案例页 / 选型指南），承接找供应商的搜索意图。

7.4 产品词：已跑通，需守护

「差分干涉卫星影像处理软件」点击率 33%、「pie 遥感软件」「pie-engine」点击率 100%。这些词用户搜到了想要的，是「已跑通」的词，排名不能掉。可围绕它们做竞品对比 / 教程类内容加固。

7.5 垃圾流量噪声（非安全问题）

移动端出现「恒星集团线路导航.6.s.tjh7ns8h9.top」等 .top 垃圾域名词，属垃圾导航站 / 爬虫刷词流量，被百度错误归因到官网。已逐页抓取官网源码验证：无黑链、无垃圾页面，是垃圾流量噪声；监测时需过滤，无需处理。

八、收录自动化（让新文章自动进 sitemap + 自动推送百度）

8.1 两处操作，两个地方

步骤做什么操作位置负责人
① 改 sitemap把博客 URL 纳入 sitemap官网服务器 / 官网后台官网建站方
② 提交地址把 sitemap 地址报给百度百度站长平台站长账号

8.2 sitemap 自动生成（一次性配置）

官网博客路径 /website/cn/pages/blog/bloginfo/XXX.html 说明文章由 CMS 发布，sitemap 大概率由 CMS 自动生成。让建站方在后台把「博客」模块纳入 sitemap 生成规则后，以后发新文章会自动带进 sitemap，无需逐篇操作。若 sitemap 是手动维护的静态文件，则每发一篇都要手工加一条，应让建站方改成自动生成。

8.3 发文自动推送百度（API 主动推送）

在 CMS 里配置：每发一篇新文章，自动调用百度主动推送 API（data.zz.baidu.com/urls，token 在百度站长后台获取），新 URL 秒级推给百度。与 sitemap 形成双保险：sitemap 兜底全站、API 推送实时单篇。

8.4 给建站方的一句话需求

博客文章要接入 sitemap 自动生成，并且发文时自动调用百度主动推送 API（token 我在百度站长后台提供），实现新文章发布后无需人工提交。

8.5 验证方法

发布一篇测试文章后，打开 https://www.piesat.cn/sitemap.xml 搜索新文章 URL：能搜到即自动更新成功；搜不到则仍为手动模式，需回头调整。
