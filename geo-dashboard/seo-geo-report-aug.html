模块二：8 月监测到的问题

2.1 技术配置问题（5 个，含 3 个致命）

优先级问题影响
P0 · 致命sitemap.xml 未收录博客文章搜索引擎发现不了博客，收录受阻
P0 · 致命robots.txt 屏蔽全部文章图片图片 SEO 全废，AI 引擎抓不到图
P1 · 重要canonical 缺失 + JSON-LD URL 错误权威地址信号错误
P1 · 重要datePublished 日期错误时效性信号错乱
P2 · 建议博客列表页 SEO 缺失入口页无 title / description / 结构化数据

实测佐证（2026-08-31）：官网 sitemap.xml 共 1058 个 URL，百度已收录 1052 个（收录率 99%）；而博客目录 bloginfo 仅 2 条被收录（A4 女娲星座组网 / B2 海洋监测）。「进 sitemap 的几乎全收、不进 sitemap 的几乎全漏」——正是 sitemap 未收录博客文章的直接后果。

问题数据含义

2.3 搜索排名问题（品牌词 / 事实词未立起来）

现象

产品词「已跑通」，品牌词 / 事实词被第三方截胡

「女娲星座卫星」搜索结果被百度百科、央广网、北京日报、今日头条、河南政府网、中新网占据，官网博客 A4 未进前列；「航天宏图上卫星」被上证报、东方财富、同花顺、九方智投、百家号等股票 / 新闻站占据，官网未出现。首期 10 条通用探测词（SAR 原理、水利 / 海洋监测等）全部零引用。

根因（四层叠加）
  1. 词性不同：产品词是「独占词」无对手，品牌词 / 事实词是「公共词」高竞争；
  2. 平台权重：百科 / 媒体 / 股票站权重远高于官网；
  3. 技术短板：P0 问题让博客文章搜不到、不被信任；
  4. 意图错配：搜「女娲星座」的人想看「最新动态」，官网给的是科普文章，且标题不直接命中该词。

2.4 垃圾流量噪声（非安全问题）

移动端出现「恒星集团线路导航.6.s.tjh7ns8h9.top」等 .top 垃圾域名词，属垃圾导航站 / 爬虫刷词流量被百度错误归因。已逐页抓取源码验证：无黑链、无垃圾页面，监测时过滤即可。

模块三：针对问题的解决方案

3.1 技术问题修复（对应 2.1）

优先级修复动作时限
P0博客 URL 加入 sitemap.xml（或单独生成博客 sitemap）立即
P0放开 robots.txt 对 /uploads/ 图片的屏蔽立即
P1单篇加 canonical 指向真实 URL；改 JSON-LD @id 与 image 为绝对 URL1 周内
P1datePublished 改为真实发布日期1 周内
P2列表页补 title / description / 结构化数据2 周内

3.2 收录自动化（治本，避免每篇手工提交）

改 sitemap 在官网侧（建站方），提交地址在百度站长侧——两步两地方。让建站方把「博客」模块纳入 sitemap 自动生成，并配置「发文自动调用百度主动推送 API」。

给建站方的一句话需求：
博客文章要接入 sitemap 自动生成，并且发文时自动调用百度主动推送 API（token 我在百度站长后台提供），实现新文章发布后无需人工提交。

3.3 转化优化（对应 2.2）

  1. 品牌词点击率：优化品牌相关页面 title + description，强化「卫星遥感 / SAR / 女娲星座」差异化标签，与百科、股票站拉开点击吸引。
  2. 移动端归零：排查移动端排名分布 + 移动端页面加载 / 排版体验，把移动端作为主要流量入口重点优化。
  3. 商业意向词：针对性产出「智慧应急监测」专题内容（方案页 / 案例页 / 选型指南），承接「找供应商」的搜索意图。

3.4 内容补位（对应 2.3）

  1. 事实词：「女娲星座」「上卫星」需产出直接命中词面的内容（星座规模 / 发射动态 / 在轨数据），对齐「看动态」的搜索意图，而非纯科普。
  2. 产品词守护：对已跑通的 pie-engine / pie 遥感软件 / 差分干涉软件，做竞品对比 / 教程类内容加固排名。
